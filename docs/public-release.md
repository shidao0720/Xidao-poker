# 私有开发历史与公开发布副本

原开发仓库保留完整历史。本地预览和私人素材仍在忽略目录中；不能从原仓库直接推送公开版，否则历史中的旧素材也会上传。`.gitignore` 只影响未跟踪文件，不会清理旧提交。

## 生成副本

先在原仓库检查并提交当前修改，然后执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/prepare-public-release.ps1
```

脚本不联网、不推送，不重写原仓库。每次创建独立时间戳目录，不覆盖旧产物：

```text
release/public-<时间>/
  repository/                 可发布：独立 Git 仓库，只有清理后的 main
  xidao-public-source.zip      可发布：当前源码，不含 .git
  audit.json                  本地核查记录
  PRIVATE-full-history.bundle 私有：原仓库全部 refs 的历史备份
  PRIVATE-filter-work/        私有：过滤中间仓库，包含旧历史备份引用
```

**绝不能上传整个 `release` 或时间戳目录。只使用 `repository` 或源码 ZIP。** Bundle 不包含忽略文件、未提交修改或数据库；私人素材仍需单独备份，数据库仍在 Docker 卷中。

## 清理范围与校验

精确排除列表在 [public-release-excludes.txt](../scripts/public-release-excludes.txt)：整个 `design-showcase`、本地素材备份目录、旧音乐、12 张 JPG 头像、旧牌面样图、两张旧 Logo PNG，以及根目录的私人开发说明。排除列表以 UTF-8 读取，支持中文文件名。保留公开 SVG、原创合成音乐、代码和英文技术文档。

仅发布 `main` 的完整祖先历史，不发布其他分支、远程跟踪引用或标签；全部原始 refs 保留在原仓库与私有 Bundle 中。每个提交仍保留作者、时间、说明和父子关系（提交编号因内容改变而变化）。只包含被排除文件的提交也不主动裁掉。旧提交的素材引用可能失效；历史用于阅读演进，当前 HEAD 才是公开版运行入口。

脚本在临时克隆中执行 Git index filter，再通过非共享传输克隆生成最终仓库，避免把过滤工具的备份引用、旧对象和 reflog 一起带过去。校验包括：

- 原仓库 HEAD 与 refs 未改变；完整历史 Bundle 可验证。
- 发布仓库只有 `main`，没有远程地址、共享对象目录或额外引用。
- 被排除路径在全部发布历史中不存在，其文件对象在整个发布对象库中也不存在。
- 当前源码树哈希与原仓库提交完全一致，`git fsck --full --strict` 通过，工作区干净。
- 生成源码 ZIP 与 SHA-256 核查记录。

这不是完整的敏感信息或版权审计；提交作者邮箱、说明和文档仍会公开。真实账户数据、数据库密码和会话数据不应提交；迁移 SQL 与示例配置是公开源码，不是运行中账户数据。

## 后续开发与 GitHub 更新

继续在原仓库开发、提交，再用相同排除规则生成新副本。不要将私有 `main` 合并到发布仓库，也不要从过滤中间仓库推送。新增待排除素材或更换路径时，先更新排除列表。

发布副本故意不配置 remote，防止误操作。确认目标 GitHub 仓库和清理策略后，再单独添加远程并推送 `main`；不使用 `--mirror` 推送。相同规则下的新发布提交一般可接续先前过滤历史，推送前仍须比较远程祖先关系；若远程有独立修改，先人工协调，不能直接覆盖。

如果目标 GitHub 仓库已经包含旧素材历史，普通推送不会清理它。覆盖远程分支、处理标签或创建新的公开仓库需另行确认；改写远程也不保证删除已有 fork、缓存和其他人下载的副本。
